# Remote Live Refresh — P0 gate status

Where the live-refresh capability stands against the **Remote Live Refresh P0**
gate checklist from the project's private design spec. This is the
production-readiness ledger: a gate is **met** only
with a passing verification (a test, a structural barrier, or a host check).
Shipping a change to production is owner-only and requires every P0 row green.

Status legend: **met** (verified in CI / structurally) · **host** (mechanism +
static checks done; the live verification runs on the target host) · **open**
(not yet built).

| Gate | Status | Verification |
| --- | --- | --- |
| **Refresh-controller path** — gateway requests refresh only via `refresh-control.sock`, never `fineco-live.sock` | **met** | Build-time: `fineco-gateway` runtime closure excludes `fineco-live` (`crates/fineco-gateway/tests/architecture.rs`). Runtime: the gateway holds only a `RefreshClient`; with none configured the live tools return a safe "not configured" error (`crates/fineco-gateway/tests/refresh.rs::live_refresh_without_a_configured_client_is_a_safe_error`). Deploy: the gateway is never in `fineco-ipc-live` (`crates/fineco-helper/tests/deploy_units.rs::gateway_joins_store_and_refresh_groups_but_never_live`). |
| **Owner-only refresh** — only `auth_id: owner` holds live-refresh caps | **met** | The three `*.live.refresh` caps are owner-only and a cached-read grant does not imply them (`crates/fineco-ipc/tests/refresh.rs::live_refresh_capabilities_parse_and_are_owner_only`, `a_cached_only_policy_does_not_grant_live_refresh`). The gateway denies a cached-only policy **before** any socket hop (`crates/fineco-gateway/tests/refresh.rs::a_cached_only_policy_denies_live_refresh_before_any_socket_hop`). |
| **Controller validation** — rejects unauthenticated / wrong-policy requests | **met** | The controller re-checks the capability against the shared read-only policy (fail closed, no `job_runs` row) and re-validates the bounded params before any preflight/refresh (`crates/fineco-helper/src/controller.rs::tests::a_policy_without_the_live_capability_denies_and_creates_no_job_row`); `serve_refresh_blocking` re-validates the envelope server-side and rejects an unknown/smuggled command (`crates/fineco-ipc/tests/refresh.rs::the_server_rejects_a_forged_command_without_reaching_the_handler`). Identity = socket-peer isolation (single-owner topology; see the plan's M8 Capability-Model note). |
| **Worker validation** — private worker rejects command/cap mismatch independently | **met** | The worker re-validates the command (closed enum, `deny_unknown_fields`) + the bounded params with the **same** shared validators, and relies on `fineco-ipc-live` socket isolation (the owner-ratified worker bar). An unknown command is rejected before any fetch (`crates/fineco-live/tests/round_trip.rs::an_unknown_command_is_rejected_with_a_safe_error_not_a_crash`); bounds are re-checked in the worker (`crates/fineco-worker/tests/reads.rs`). A signed identity envelope is a documented future hardening (plan note). |
| **Default no-payload response** — refresh returns operation/snapshot status only | **met** | `RefreshOutcome` carries `data_area` / `captured_at` / `snapshot_id` / a row `count` — never a value (`crates/fineco-ipc/tests/refresh.rs`, `crates/fineco-helper/src/controller.rs::tests::portfolio_refresh_captures_and_returns_status_only`). Values are read afterward via the cached tools. |
| **Concurrency lock** — second refresh per area returns `already_refreshing` | **met** | `refresh_preflight` checks the running-job lock first (`crates/fineco-refresh/src/lib.rs` preflight tests); the refresh accept loop is single-consumer and `already_refreshing` is the authoritative cross-connection guard (`crates/fineco-helper/src/serve.rs` comment). |
| **4xx behavior** — Fineco auth failures → `auth_required`, no auto-retry | **met** | `auth_required` is non-retryable; `with_retry` does not retry it; the controller records the failed attempt without retrying (`crates/fineco-helper/src/controller.rs::tests::an_auth_failure_propagates_without_retry_and_records_the_job`). |
| **5xx behavior** — no controller re-login retry + circuit breaker | **met** | The controller does not retry a transient `fineco_timeout` by re-entering the live worker (`controller.rs::tests::a_transient_timeout_does_not_reenter_the_live_worker`), so one admitted live operation maps to at most one worker call / Fineco login; authenticated-market reads additionally debit their own market-only fresh-login budget from the worker's status-only session facts. Worker-side failures after an admitted market read, including `internal`, also debit conservatively; only local live-socket connect/write failures use `live_transport_failure` and avoid login accounting. The per-area circuit breaker opens after N upstream/timeout failures and half-opens after a cooldown (`crates/fineco-refresh/src/lib.rs` circuit tests). Body-read timeouts classify as `fineco_timeout`, not `internal` (`crates/fineco-worker/tests/timeout.rs::a_stalled_private_read_body_times_out`). |
| **Auditability** — who/when/data-area/status, no payload | **met** | The gateway emits one allowlist-by-construction audit line per refresh (`credentialed_live` data class, a row count, never a value); the anti-leak test covers the audit record shape (`crates/fineco-gateway/tests/audit.rs`). The controller's `job_runs` rows record area/status/safe-code/timestamps. |
| **Egress control** — worker reaches Fineco only; arbitrary egress fails | **met** (live-verified on the deployment host) | The nftables `meta skuid "fineco-worker"` allowlist pins the worker to the resolved Fineco IPs + pinned DNS, with a family-agnostic deny before the broad `tcp/443`; the timer atomically replaces the sets (`flush`+`add` in one `nft -f`) to handle IP rotation with no deny window (`deploy/firewall/`). CI guards verify the ruleset shape. **Live-verified on the deployment host:** as `fineco-worker`, a TCP connect to a Fineco IP (in the allow set) succeeds and a connect to `<blocked-test-ip>` is dropped; the deny rule's counter increments. (The `meta skuid` match + the setgid socket-group inheritance both work on the unprivileged-LXC host kernel.) |
| **Gateway egress control** — the internet-facing gateway reaches only its targets (CF JWKS + enrichment + ETF); arbitrary egress fails | **met (mechanism + CI + per-target egress verified on the deployment host)** | A parallel `meta skuid "fineco-gateway"` block pins the gateway to the same pinned resolvers + a `fineco_gateway_v4/v6` set (resolved by the egress-set from the JWKS host, the config-only enrichment host, and `images.finecobank.com`), with a family-agnostic deny before the broad `tcp/443` — so a compromised gateway can no longer exfiltrate to an **arbitrary** host. UNLIKE the worker, the block accepts loopback FIRST (the gateway serves cloudflared over IP loopback); allowlisted HTTPS — including established packets — is accepted by the dport-443-to-set rule. The gateway uid rules (including the deny) are evaluated BEFORE the chain-wide `established,related accept`, so an established flow to an IP that has rotated OUT of the set still hits the gateway deny. `fineco-gateway.service` orders `After=` the egress-set (its startup JWKS fetch is fail-closed). CI guards verify the ruleset shape + the loopback-before-deny ordering. **Residual (owner-ratified, accepted):** this is **IP-level** pinning, not SNI/host-level — the JWKS + ETF targets are CDN-fronted, so the allowlisted edge IPs may also serve OTHER hostnames, and a hijacked gateway could in principle exfiltrate to a different site sharing those IPs. Airtight host-level egress would need an L7 hostname-policy proxy; the plan weighed that against the timer-refreshed nftables address set and the owner chose the lighter IP-set (a real reduction — arbitrary non-CDN exfil is blocked — without an L7 proxy in the credentialed path). **Live-verified on the deployment host:** as `fineco-gateway`, a TCP connect to **each** target on `:443` — the CF JWKS host, the config-only enrichment host, and the ETF CDN — **succeeds through the allowlist**, while a connect to `1.1.1.1:443` is **dropped** and the `fineco-egress-deny gateway` counter increments. The gateway also boots **active** (its startup JWKS fetch is fail-closed) and a loopback un-JWT request returns **401** (Access enforced; the tunnel/MCP path is unaffected). The per-target connect proves the nft allowlist permits the gateway→target path (rather than inferring it from boot, which only exercises JWKS); the full app-level fetch (DNS + TLS + parse) runs when the market tools are invoked. **End-to-end confirmed:** `market_get_zero_commission_etfs` returned a fresh result set with a current `captured_at` (a live fetch through the deployed gateway, not the cache) — so the ETF-host app-level egress is exercised, not just IP-reachable. |
| **Alerting** — refresh spike, budget exhaustion, auth failures, market auth/upstream/circuit/recovered-session events, egress denies (worker + gateway), worker restart loop, scheduled-refresh failure | **met** (mechanism + CI + host-verified on the deployment host for the original live-refresh sources) | The alerting is **wired**: `deploy/alerting/fineco-alert.sh` + `fineco-alert.{service,timer}` scan the payload-free sources below and pipe any fired alert to a notifier-agnostic command (`FINECO_ALERT_COMMAND` in `/etc/fineco/alert.env`, default `logger -t fineco-alert`). Delivery is **at-least-once**: the journald cursor + counter baselines advance via a staging copy committed only after every delivery succeeds, so a broken notifier re-fires rather than dropping an alert. The live-refresh and authenticated-market journal alerts are proven to fire end-to-end — the first run to only seed, and a failed delivery to re-fire — against stubbed sources in `crates/fineco-helper/tests/alerting.rs`; the unit/script shape is guarded in `crates/fineco-helper/tests/deploy_units.rs`. **Host-verified on the deployment host for original sources:** with `fineco-alert.timer` enabled, the seed run emitted nothing; after inducing a worker egress deny (worker→`<blocked-test-ip>`) one scan produced the expected private-worker egress-deny alert with a `<counter-delta>` in the journald sink. |

## Authenticated Market Live-Session Addendum

Authenticated market reads share the live Fineco session risk but return
`authenticated_market` data rather than refresh snapshots. The current
implementation has the controller-mediated path and status-only worker boundary
in place for `market_search_asset` and `market_get_asset_details`: gateway ->
`market-control.sock` -> controller -> `fineco-live.sock` -> private worker,
with `MarketSearchLiveResult` / `MarketAssetDetailsLiveResult` carrying
`MarketSessionStatus` (`login_performed`, `session_reused`, `session_evicted`,
`reused_session_401_recovered`, optional expiry TTL) and no cookie values, auth
headers, raw `Set-Cookie`, or session handles. The worker is still stateless
across calls and reports `login_performed: true` for authenticated market reads.

Refresh and authenticated market reads share only the controller-local
one-in-flight live-session operation lock. Authenticated market reads enforce
their own market fresh-login policy: at most 12 fresh logins per rolling hour and
a 60s minimum fresh-login cooldown, finalized from the worker's
`MarketSessionStatus`, so a future `session_reused` response will not burn a
fresh-login slot, while `reused_session_401_recovered` does burn a fresh-login
slot. Scheduled refreshes keep their refresh-preflight gates and do not burn or
obey the market budget/cooldown. Authenticated-market reads also have a
controller-local circuit breaker that opens after three consecutive market
upstream/timeout failures and half-opens after 600 seconds. The gateway audit
line may include these session booleans as status-only metadata, never cookies or
handles; the alert scanner keys on those audit metadata fields for market
auth/upstream/circuit/recovered session events. Cross-call reuse TTL remains
unset until cookie-lifetime evidence exists, so the worker reports a fresh login
for search today.

`market.authenticated.read` is still deliberately absent from the checked-in
deployment policy and connector defaults. Granting it is an owner decision after
the milestone diff and market live-session gate are reviewed clean.

## Alerting — named alerts and their verification sources

The plan's *Observability → Minimum alerts*, scoped to live refresh. Each alert is
driven off an existing, payload-free signal (a structured log line, a counter, or
a systemd state) — no new instrumentation in the credentialed path. The scan
(`deploy/alerting/fineco-alert.sh`, run by `fineco-alert.timer` on boot + every
~3 min) reads only NEW events since its last run (a persisted journald cursor +
last-seen counters under `/var/lib/fineco-alert`) and pipes any fired alert to the
notifier command from `/etc/fineco/alert.env` (default `logger -t fineco-alert`).

| Alert | Fires on | Verification source |
| --- | --- | --- |
| **Egress deny (private worker)** | denied worker egress packets | **The nft deny-rule COUNTER** — `nft list chain inet fineco output` → the `skuid <fineco-worker-uid> … counter packets N … drop` rule; alert on `N` increasing. **NB (verified on the LXC):** the rule's `log prefix "fineco-egress-deny private-worker "` does **not** surface in the unprivileged LXC's `journalctl -k` *or* the host `dmesg` (netfilter log routing), so the **counter is the reliable source**, not the log line. **Debounce:** the worker's allow rules accept HTTPS (including established packets) to IPs *currently* in the set, but the worker uid rules (including the deny) are evaluated BEFORE the chain-wide `established,related accept` — so an established flow to an IP that has rotated OUT of the set hits the worker deny. Benign CDN rotation (and a brief cold-start window before the set first populates) can therefore produce transient denies; alert on a *sustained* counter increase, not a single packet. |
| **Egress deny (gateway)** | denied gateway egress packets — a **compromised internet-facing gateway** trying to exfiltrate cached private data to a non-allowlisted host | **The nft deny-rule COUNTER** for the `fineco-egress-deny gateway` rule (same `nft list chain inet fineco output` read, scoped to the `gateway` label so it never conflates with the worker counter). Same caveat as the worker (the log line doesn't surface; the counter is the source) and the same rotation debounce. The gateway block accepts loopback first and allowlisted HTTPS (including established packets) to IPs currently in the set; the gateway uid rules (including the deny) run BEFORE the chain-wide `established,related accept`, so an established flow to a rotated-out allowlisted IP can also hit the deny. Alert on a *sustained* increase (a genuine exfil attempt), not benign CDN-rotation blips. |
| **Live-refresh budget exhausted** | the daily per-area budget is hit | the gateway audit line `outcome:error error_code:refresh_budget_exhausted` (and the controller returns it). `journalctl -u fineco-gateway -o cat | grep refresh_budget_exhausted` |
| **Repeated Fineco auth failures** | live refresh keeps returning `auth_required` | `job_runs` rows `status=failed safe_error_code=auth_required` for the area, and the audit `error_code:auth_required`. Alert on a count over a window. |
| **Circuit breaker opened** | N consecutive upstream/timeout failures | the audit `error_code:refresh_circuit_open` (the controller returns it once the breaker is open) + the `job_runs` failure streak that tripped it. |
| **Refresh spike / off-window** | more refreshes than expected, or outside the owner's window | the gateway audit lines `tool:private_*_refresh_live_sensitive` (count over time). |
| **Repeated Fineco authenticated-market auth failures** | authenticated market tools keep returning `market_auth_required` | gateway audit lines for `tool:market_search_asset` / `market_get_asset_details` with `error_code:market_auth_required`. Alert on a count over a window; cached/private tool auth errors do not match. |
| **Authenticated-market upstream failures** | authenticated market tools keep returning retryable upstream/timeout errors | gateway audit lines for authenticated-market tools with `error_code:market_upstream_failure`, `fineco_timeout`, or `fineco_upstream_error`. Alert on a count over a window. |
| **Authenticated-market circuit breaker opened** | the market controller circuit opens after repeated market upstream/timeout failures | gateway audit lines for authenticated-market tools with `error_code:market_circuit_open`; controller tests cover open and half-open behavior. |
| **Authenticated-market reused session recovered after 401** | a stale reused session was evicted and repaired by the one allowed fresh-login retry | successful authenticated-market audit lines with `reused_session_401_recovered:true`; the controller debits this as a fresh-login slot. |
| **Worker restart loop** | the private worker keeps failing/restarting | `systemctl show -p NRestarts fineco-private-worker` / `journalctl -u fineco-private-worker` (the unit is `Restart=on-failure`). |
| **Scheduled refresh failed** | the unattended Mon–Sat portfolio refresh fails (SCA / timeout / gate denial) | the refresh one-shot's journal line `fineco-helper: refresh failed: …`, read on the **same cursor** as the gateway journal (`journalctl -u fineco-gateway -u fineco-refresh-portfolio.service`). Threshold 1 — a once-daily unattended refresh failing even once means the day's refresh did not happen. (Scheduled refreshes run via the controller, not the gateway, so they leave **no** gateway-audit line — hence this dedicated source.) |

> None of these read or expose a payload — the audit record is allowlisted by
> construction, the `job_runs` rows hold only area/status/safe-code/timestamps,
> and the egress log line carries only the deny metadata.

## Accepted security residuals (post-review, owner-ratified)

Conscious, **owner-ratified residuals** from the security review — explicitly
**accepted, not silently "done"** — for this single-owner, owner-only deployment.
Each is low-severity given the topology, with a documented revisit trigger. (The
**IP- vs SNI-level egress** residual is recorded in the gateway-egress gate row above.)

| Item | Residual | Why accepted (low severity here) | Revisit when |
| --- | --- | --- | --- |
| **#2 DNS exfil / resolver trust** | The worker + gateway may send DNS to the pinned resolvers, and the egress allow-sets are populated from resolver answers — so DNS is an exfil channel and a poisoned resolver could steer the allow-set toward attacker IPs. | The big win (arbitrary HTTPS exfil from the gateway) is now **closed**; this is a different, lower severity. DNS is required to resolve the rotating Fineco/CDN IPs; the resolvers are pinned, and the IP allowlist + TLS certificate validation are the layered mitigations. | A DoT/DoH-to-pinned-resolver hardening is wanted, or resolver trust degrades. |
| **#5 Origin validation optional** | When `FINECO_ALLOWED_ORIGINS` is **empty, Origin validation is OFF entirely** — `Gateway::with_allowed_origins` accepts requests carrying **any** browser `Origin`, not just Origin-less ones (so the exposure is broader than "headless clients only"). Separately, even **with** an allowlist configured, a **missing** `Origin` is still allowed. | The real auth gate is the Cloudflare Access **JWT verified on every request**, plus loopback `Host` validation and tunnel-only origin; the owner's clients are native (service token / connector OAuth), neither of which is a browser CSRF context. | The client becomes browser/cookie-oriented — then set `FINECO_ALLOWED_ORIGINS` (turns validation on) and decide whether to also reject missing-`Origin`. |
| **#8 Alert notifier runs as root** | The alert one-shot runs as root (it needs the gateway/worker journals + the nft counter) and execs `$FINECO_ALERT_COMMAND`; UID 0 can read `/etc/fineco` secrets. | Already far safer than a root shell: fixed config path with ownership/mode validation, **no** systemd `EnvironmentFile`, capability-dropped notifier exec (`setpriv`), payload-free stdin. The residual is only the UID-0 read of `/etc/fineco`. | A non-root notifier-user split is wanted; not P0-blocking. |
